# P2. bench 이식

목적: bench 사본을 Windows에 맞게 이식하고 전후 테스트 결과를 남긴다.

## 붙여 넣을 프롬프트

```text
docs/03-safety-rules.md를 지킨다. 묶음 루트 아래 `port/` 폴더를 새로 만들고(이미 있으면 멈추고 묻는다) reference/ 폴더 전체를 그 안으로 복사한다. 이 폴더의 절대 경로를 사람에게 보이고, 이후 단계에서 PORT라고 부른다. PORT/notes.md를 만들어 P1 결과 표를 옮겨 적는다. 시험이 workbench/의 형제인 roles/·harness/·policy.example.yaml을 찾으므로 workbench/만 따로 떼지 않는다. 원본과 기존 작업 결과는 덮어쓰지 않는다. 복사한 디렉터리의 workbench/에서 수정 전에 다음 명령을 실행해 성공·실패·건너뜀과 오류를 기준 결과로 남긴다. 시험 전에 Python에 PyYAML과 tzdata가 있는지 본다. bench는 import할 때 시간대 'Asia/Seoul'을 읽는데 윈도우 Python에는 시간대 데이터가 없어 tzdata 패키지가 필요하다. 없으면 설치 명령(`<Python> -m pip install PyYAML tzdata`)을 보여 주고 사람이 실행할 때까지 기다린다. 시험은 hc·claude·codex를 실제로 부르지 않는다(가짜 실행 파일을 쓴다. 이 셋이 없는 리눅스 컨테이너에서도 통과했다).

python -m unittest discover -s tests -p "test_*.py"

docs/02-platform-points.md의 1절 B1~B16을 각각 확인하고 사본을 Windows에 맞게 고친다. 항목마다 Windows에서 해당 동작이나 경계 조건을 검증하는 테스트를 1개 이상 추가한다. B1은 수신함의 배타 잠금과 해제 범위를 유지하고, B3은 자식 환경에서 API 키 2개를 제거하는 기능을 유지한다. 키 값은 읽거나 출력하지 않는다. Windows에서 직접 확인해야 하는 경로, 셸과 프로세스 동작은 추측하지 않는다. 각 항목의 수정 내용과 테스트 결과를 B1~B16별로 정리해 PORT/notes.md에 적는다. B4에서 정한 Python 실행 파일 설정 키 이름도 notes.md에 적는다. P3가 그 이름을 쓴다.

수정 후 같은 전체 테스트 명령을 다시 실행한다. 실패와 건너뜀도 그대로 보고한다. 설치판이나 사람의 설정을 바꿔야 한다면 변경할 경로와 내용을 미리 보여 주고 사람이 직접 적용할 때까지 멈춘다. 확인할 수 없는 항목은 '확인 필요'와 이유를 남긴다.
```

## 확인할 결과

PORT의 절대 경로와 notes.md가 보여야 한다. 수정 전후의 전체 테스트 명령과 성공·실패·건너뜀, B1~B16 각각의 수정 및 추가 테스트 결과가 보여야 한다. B1 잠금과 B3 키 제거가 유지되는지 확인한다. 테스트 실패는 통과로 취급하지 않는다. 다음 단계로 가는 기준은 실패 0이거나, 남은 실패마다 사람이 받아들인 이유가 notes.md에 적혀 있는 것이다.

## 멈출 때

원본이나 필수 의존성이 없거나, 잠금·키 제거를 유지할 수 없거나, 실패 원인을 해결할 수 없으면 출력과 남은 항목을 보존하고 멈춘다.
