# P4. mod와 레이아웃

목적: 기존 설정을 보존하며 Windows용 mod와 레이아웃을 준비한다.

## 붙여 넣을 프롬프트

```text
docs/03-safety-rules.md를 지킨다. reference/workbench/README.md의 'Herdr 업데이트 뒤 트리 재생성'과 docs/02-platform-points.md의 2절 M1~M6을 읽는다. 설치된 Herdr의 도움말에서 Windows 명령 이름과 mod·레이아웃 경로를 확인한다. 명령 이름이 다르거나 확인되지 않으면 추측하지 않고 멈춘다.

기본 agents, files, menu mod를 herdr-app do mod.clone으로 각각 아직 없는 새 이름에 복제하고, 기본 레이아웃도 아직 없는 새 이름에 복제할 계획을 세운다. 트리, Files, 메뉴 생성기의 입력·출력 경로와 인자를 확인하고 복제본에 생성기를 적용한다. README 예시의 `/tmp/...` 경로는 맥 경로이니 쓰지 말고 PORT 아래 임시 폴더를 쓴다. 메뉴 생성기의 HUB 값(build_wb_menu.py의 HUB)에 넣을 폴더는 P3의 `cwd`로 하되 사람에게 확인받는다. md와 선택적인 PR mod도 새 이름으로 준비한다. M1~M6을 Windows에 맞게 각각 검토하고 필요한 변경을 적용한다. PR 패널이 필요하면 조직 값과 인증 위치를 사람이 확인한다. 필요 없으면 새 레이아웃에서 해당 패널을 제외한다.

Herdr 설정 위치에 쓰는 모든 단계는 실행 전에 대상 경로, 복제 이름, 명령과 변경 내용을 보여 준다. 사람이 직접 적용할 때까지 기다린다. 기존 mod와 레이아웃은 덮어쓰지 않는다. 생성기의 기준 위치가 맞지 않으면 억지로 적용하지 않고 중단한다. 만들어진 각 mod 폴더에 herdr-app check <mod 폴더>를 실행해 결과를 보고한다. 새 레이아웃의 적용은 사람이 직접 한다.
```

## 확인할 결과

새 mod와 레이아웃의 이름과 경로, M1~M6별 변경 또는 해당 없음의 근거가 보여야 한다. 각 `herdr-app check`가 통과해야 한다. 기존 mod와 레이아웃이 보존되고 실제 레이아웃 적용은 사람이 해야 한다.

## 멈출 때

Windows 명령이나 경로를 확인할 수 없거나, 생성기가 기준 위치를 찾지 못하거나, 검사에 실패하면 출력을 남기고 멈춘다. 사람이 설정 변경을 적용하기 전에는 다음 단계로 가지 않는다.
