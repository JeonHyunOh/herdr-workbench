# Windows 직접 이식 프롬프트

Herdr를 열고 작업 폴더에서 Claude Code 1개를 띄운다. [P0](P0-context.md)부터 [P6](P6-trial.md)까지 순서대로 각 파일의 코드 블록을 하나씩 붙여 넣는다. 단계마다 '확인할 결과'를 사람이 확인한 뒤 다음으로 간다. 막히면 멈추고 그 단계의 출력과 오류를 남긴다. P0부터 P6까지 같은 Claude 세션에서 이어 간다. P2가 만드는 이식 폴더(이후 PORT)의 `notes.md`에 단계마다 결과를 남겨, 세션이 끊겨도 다음 단계가 앞 결과를 읽을 수 있게 한다. 비밀값은 기록하지 않는다. 모든 단계에 [안전 규칙](../docs/03-safety-rules.md)을 적용한다.

| 단계 | 바꾸는 곳 | 사람이 할 일 |
|---|---|---|
| P0 맥락 | 없음 | 이해 요약과 빠진 자료를 확인한다. |
| P1 설치 확인 | 없음 | 버전, 실행 위치, 스페이스 id 확인 결과를 본다. 로그인은 직접 확인한다. |
| P2 bench 이식 | 작업 폴더의 코드 사본과 테스트 | 전후 테스트 결과와 B1~B16별 결과와 PORT/notes.md를 본다. |
| P3 설정 | 작업 폴더의 `bench.yaml` | 경로와 내용을 미리 보고 승인한 뒤 저장하게 한다. |
| P4 mod | 새 mod와 새 레이아웃, 필요 시 작업 폴더의 생성기 사본 | Herdr 설정 위치의 변경을 미리 보고 직접 적용한다. 검사 결과를 보고 레이아웃도 직접 적용한다. |
| P5 역할 | 지정한 역할 폴더 | 5개 파일과 자리표시자 결과를 확인한다. 사람 설정을 건드리는 경우 직접 적용한다. |
| P6 리허설 | 연습용 빈 Git 레포, 워크트리와 작업대 기록 | 세션 계층과 보고·정리 결과를 보고 승인 창에 직접 답한다. |

Windows에서 실행한 검증 결과는 아직 없다. 각 단계의 '확인 필요' 항목은 PC에서 확인한다. 필요한 파일이 묶음에 없다면 건너뛰지 말고 준비될 때까지 멈춘다.
