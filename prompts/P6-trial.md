# P6. 리허설

목적: 연습용 레포에서 세션 계층과 보고·정리를 확인한다.

## 붙여 넣을 프롬프트

```text
docs/03-safety-rules.md를 지킨다. 이전 단계의 필수 검증이 끝났는지 확인한다. 사람에게 경로를 보여 준 뒤 실제 업무 자료가 없는 연습용 빈 Git 레포와 별도 작업 폴더를 준비한다. close는 매번 origin/main을 fetch해 머지 여부를 본다(PORT/workbench/README.md의 close 설명). 그래서 연습 레포에는 origin이 필요하다. 필요한 경우 외부에 게시하지 않는 연습용 로컬 원격을 준비하고 조건을 충족한다. 기존 레포와 원격은 건드리지 않는다.

디렉터는 Herdr 터미널에서 사람이 먼저 연다. 예: `<Python> PORT/workbench/bench.py --config PORT/workbench/bench.yaml spawn --role secretary --vendor claude --model claude-opus-5-5 --cwd <연습 폴더> --display 디렉터` (PORT는 실제 절대 경로로). 그 디렉터가 리드 1개를 열고, 리드가 작업자 1개를 열도록 한다. 작업자에게 연습용 레포에서 안전하게 수행할 작은 작업을 지시한다. 트리에서 디렉터 → 리드 → 작업자의 계층이 보이는지 확인한다. 작업자의 보고가 리드 수신함에 도착하는지, 리드가 close로 작업자 세션과 조건을 충족한 워크트리를 정리하는지, 리드의 보고가 디렉터 수신함에 도착하는지 확인한다. 변경 사항이나 미push 등으로 close가 보존한다면 강제로 지우지 않고 이유를 보고한다. Windows Codex 작업자가 워크트리 안에서 파일 쓰기·테스트·커밋을 승인 없이 할 수 있는지도 확인한다. 승인 또는 trust 창에는 사람이 직접 답한다.

각 단계의 실제 결과, 확인한 화면·명령 출력, 정리되지 않은 항목과 오류를 보고한다. 확인하지 못한 것은 '확인 필요'로 남긴다.
```

## 확인할 결과

트리에 3개 역할의 부모·자식 관계가 보여야 한다. 작업자 보고는 리드에게, 리드 보고는 디렉터에게 도착해야 한다. `close` 결과에서 세션과 조건을 충족한 워크트리가 정리됐는지 확인한다. Codex 작업자의 Windows 샌드박스 동작도 별도로 기록한다.

## 멈출 때

부모·자식 관계나 보고 대상이 다르거나 정리 조건이 충족되지 않으면 결과를 보존하고 멈춘다. 승인 창에는 사람이 답할 때까지 기다린다.
