# WSL2 갈래에서 아직 안 되는 것

작업대 도구를 고치는 쪽에 넘긴 변경 목록이다. 들어오면 이 문서와 [README.md](README.md) 7절을 고친다.

| # | 안 되는 것 | 이유 | 그동안 쓰는 방법 |
|---|---|---|---|
| G1 | 작업대 트리(계층·역할·모델·안 읽은 보고 수·내 순서) | 트리 mod는 윈도우 앱 안에서 돌고 bench 파일(`bench.yaml`·`tree.json`)은 WSL 안에 있다. 생성기가 `readTextFile`·`exec`에 머신 지정(`{ on: <머신> }`)을 넣지 않는다 | Herdr 기본 Agents 패널과 `bench ls` |
| G2 | 트리의 주소 대조 | 앱은 다른 머신의 주소와 스페이스 id에 `<머신>/` 접두를 붙이고 bench 기록에는 접두가 없다 | G1과 같다 |
| G3 | Files 패널의 md 렌더링으로 결과 파일 열기 | `wb-files`가 절대 경로 파일을 앱이 도는 컴퓨터에서 연다. 열기 단추가 macOS `open`이다 | Herdr 기본 Files 패널, 또는 WSL 안에서 직접 연다 |
| G4 | 터미널 우클릭 'Files에서 열기' | `wb-menu`의 허브 경로가 생성기에 고정돼 있고 `sh`를 앱 쪽에서 부른다 | 결과 파일은 절대 경로로 보고하게 하는 역할 규칙을 그대로 쓴다 |
| G5 | md 뷰어의 Finder 단추 | macOS 전용 명령이다 | 쓰지 않는다 |
| G6 | '내 PR' 패널 | 조직 이름(`ORG`)을 채워야 하고, `gh`가 윈도우·WSL 중 어디에 로그인돼 있는지에 따라 호출 위치가 달라진다 | 레이아웃에서 빼거나 GitHub 화면을 쓴다 |
| G7 | 새 세션 탭 이름 바꾸기 | `bench.yaml`의 `herdr_app`은 앱 명령 경로인데 WSL 안에는 앱이 없다. WSL에서 윈도우 앱 명령을 부를 수 있는지는 확인하지 않았다 | 비워 둔다. 기능이 꺼질 뿐 spawn은 된다(원본 커밋 88ea179의 시험으로 고정) |
| G8 | 고침(0684dd5). Codex MCP 신원 확인의 대체 경로 | MCP가 `HC_TERMINAL_ID`를 받지 못했을 때 bench는 부모 프로세스를 거슬러 Codex를 찾는다. 리눅스 `ps`의 `comm`은 실행 파일 이름만 줘서 경로 대조가 맞지 않았다. 이제 리눅스에서는 `/proc/<pid>/exe`로 전체 경로를 읽는다 | 해당 없음. 우분투 컨테이너에서 `tests/test_process_linux.py` 7개 통과 |
