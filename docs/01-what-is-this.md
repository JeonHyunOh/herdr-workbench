# 01. 작업대란

작업대는 일을 완성해 주는 제품이 아니라, 사람과 에이전트가 일을 시작하고 결과를 살펴보는 작업 환경이다. Herdr 안에 실제 Claude Code와 Codex 명령줄 프로그램을 연다. 세션 트리는 폴더 목록처럼 부모와 자식을 들여써 보여 준다. 사람은 디렉터와 리드의 2개 층을 중심으로 진행 상황과 판단을 살핀다. 작업자가 답을 기다리거나 안 읽은 보고가 있으면 그 표시가 부모 리드 줄에도 보인다. Codex 세션은 사람이 직접 열지 않고 디렉터나 리드가 연다. 각 프로그램은 API 키가 아닌 구독 계정 로그인으로 사용한다.

## 구성 요소

- **Herdr 앱**: 터미널과 패널을 표시한다. **herdr-core의 `hc`**는 터미널을 열고 상태를 확인한다.
- **bench**: `spawn`으로 자식 세션을 열고 `report`, `inbox`, `ack`로 보고를 주고받는다. `ls`로 세션을 확인하고 `close`로 끝난 자식을 정리한다.
- **`native_exec.py`**: 자식 CLI를 실행하는 감싸기 프로그램이다. 자식 환경에서 API 키를 제거한다.
- **mod**: Herdr의 패널이나 메뉴를 바꾸는 확장이다. 트리는 세션 계층을 표시하고 Files는 파일을 살핀다. 메뉴는 파일 열기를 돕고 md는 문서를 표시한다. PR mod는 선택적으로 PR을 표시한다.
- **레이아웃**: 트리와 패널의 배치를 정한다.
- **역할 지시문 5개**: 디렉터, 리드, 코딩·검토·조사 작업자의 책임과 보고 방법을 정한다.
- **정책 파일**: 작업의 자율 실행과 사람 판단 범위를 적는다. **수신함**은 부모와 자식 관계, 보고와 확인 상태를 기록한다.

## 일의 흐름

디렉터가 일을 나누어 리드를 열고, 리드는 범위와 완료 조건을 정해 작업자를 연다. 작업자는 결과와 검증을 등록된 부모인 리드에게만 보고한다. 리드는 결과를 살피고 디렉터에게 보고한다. 끝난 작업자의 정리는 리드가 `close`로 수행한다. 변경 사항이나 미push 커밋 등 정리 조건에 맞지 않으면 워크트리와 브랜치를 보존한다.

bench는 세션과 기록을 관리하는 도구이며 정책 엔진이 아니다. 승인 대화상자에 대신 답하지도 않는다. 사람과 에이전트는 [안전 규칙](03-safety-rules.md)을 따르고, 운영체제별 차이는 [플랫폼 점검](02-platform-points.md)에서 확인한다.
